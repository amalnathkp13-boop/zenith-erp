# Main dashboard header verification

The main screen is `component/zenith-erp-app/screen/zenith/Dashboard.xml`. Its page-specific styles and lifecycle are in `screen/zenithstatic/css/main-dashboard.css` and `screen/zenithstatic/js/main-dashboard.js`. `ZenithApp.xml` supplies the Bootstrap shell and asset versions; `qapps-nav.js` supplies the Quasar navigation.

The dashboard header and date controls follow the supplied ZetaERP HTML mockup and two screenshots. The header spans the page above the sidebar. The date strip has Customize, a formatted date or date range, next-range navigation, and four preset tabs. It opens on the current week and has no All time option. Clicking Today, This Week, This Month or This Year applies that preset's dates and displays them in the date control. Applied ranges that exactly match a day, calendar week, month or year select the corresponding preset. A one-day range for today displays one date and highlights Today; Customize retains the selected range.

Quasar search previously allocated no usable width to the input and indexed module names only. Both surfaces now keep the input and dropdown usable, and include the permission-filtered All Modules links. Quasar also searches screens from its existing module route map, excluding sidebar modules hidden by its existing plan filter. Arrow keys, Enter, Escape, and Ctrl/Cmd+K work. Module access is still enforced by the application.

The module grid has full card containment, its complete border, and at least 32px of space afterward. The Quasar footer follows the dashboard instead of overlapping it. Header and footer styling is scoped to the home dashboard; other pages retain their existing shell.

Run `verify-header.cjs` with Playwright available through `NODE_PATH` and the existing local demo runtime on localhost:8080. Optional settings: `DASHBOARD_BASE_URL` (localhost only), `DASHBOARD_ORGANIZATION`, `SMOKE_USER`, `SMOKE_PASS`, and `DASHBOARD_OUTPUT`. Defaults use the documented local demo account. The browser checks do not save preferences or business records. External network requests are blocked. Screenshots, detailed results, and the local session stay in ignored `tmp/dashboard-review/header` and must not be committed.

Verified on both `/apps` and `/qapps` at 320, 390, 600, 768, 900, 1024, 1280, 1440, 1907 and 2560px: no document overflow or toolbar overlap, usable search input, visible/clickable search dropdown, bounded date popup, complete module border and bottom spacing. Interaction checks cover screen search, keyboard/mouse navigation, hidden-module exclusion, All Modules search, New Sales Order and Credit Bills destinations, all four date preset bounds and active states, full calendar week/month/year matching, single-day date labels, custom date submission, next-range navigation including a year boundary, unsaved Customize controls, footer clearance, and the sidebar rising with the header then staying at the viewport top during page scroll. All 20 viewport checks passed with no browser errors.

The existing `docs/infra/ci/home-dashboard-regression.mjs` also passed authentication, invalid/reversed date bounds, monthly/annual buckets, filter context and the six Quick Action destinations. The Sales Order and Credit Bills cards point to their intended pages. Both XML screens parse, both JavaScript assets pass syntax checks, and all four repository guards pass locally. Changed source files were copied into the local Moqui container and verified against the served assets. The local preview was opened before pushing the branch or creating the PR.

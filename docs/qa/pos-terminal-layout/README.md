# POS terminal viewport and layout regression

On the live MARUTHI `/apps/zenith/pos/Terminal` at 1280×720, the empty Normal cart stretched below the viewport and its only product search began around y=796 even after the quick-start panel was dismissed. Normal intentionally has no catalog in the approved Drive reference, so the cashier could not see how to add a product. The shared POS theme forced the main pane to keep its intrinsic height while the header, action bar, customer card and footer also occupied space.

This change allows the desktop Normal cart/customer panes to shrink and scroll within a 254px minimum workspace. The scanner/search field stays visible. Stacked mobile panes keep their existing page-scroll behavior. Help starts collapsed and its button sits in the action bar. The existing Normal/Advanced layout choice moves into the Modes menu, separate from sales mode, without changing either sales-mode transition. Advanced retains the catalog and its product form actions. No POS service, tax, payment, invoice, session or org-scoping code changes.

The live reproduction used only read-only navigation, DOM geometry and hit testing; no production cart, session or bill was changed. The focused test uses `POS_UI_QA` synthetic records on a fresh loopback memory database. It verifies the empty search in the 720px viewport, the help/menu controls, an Advanced grid product click, a Normal search addition, exactly one resulting cart line with quantity two, no invoice/payment/completed bill, and narrow-screen reachability. The existing POS reference suite tests both `/apps` and `/qapps` native screens and records its independent billing-table before/after hashes. POS Billing navigation on `/qapps` links to the `/apps` terminal; the cashier screen itself is `/apps`.

Run `docs/qa/pos-reference/verify-runtime.cjs` first against a fresh disposable POS reference runtime, then `verify-runtime.cjs` in this directory with the same `POS_REFERENCE_*` environment variables. Both scripts reject non-loopback targets. Restart the disposable runtime for a repeat run because the focused test intentionally opens a synthetic session and adds an unpaid cart line. Stop the named runtime afterward and confirm the memory database is gone. Never run these fixtures against MARUTHI or another live tenant.
